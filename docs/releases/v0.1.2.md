## NX Panel v0.1.2

### Before you update

- **This release installs from the update button** (Settings → Panel update), or with the install script as before. **Take a backup first.** A backup restores only into the version that took it.
- **Update the panel first, then the nodes.** This panel works with nodes on v0.1.1. Node v0.1.2 brings OpenConnect DTLS back and the WARP+ licence key; a node from before refuses a WARP outbound that carries a key, so update the nodes before you set one.
- **Over HTTPS, everyone logs in once more after the update.** The panel's cookies changed (below), so the old login is not read any more. A panel on plain HTTP keeps its logins.
- **From this release on, the update button installs only releases signed by NX.** A release that is published but not signed yet is shown as available and refused ("not signed yet"), and the panel is left untouched.
- **The daily release check now asks nx-panel.org first**, if nx-panel.org does not answer, the panel asks GitHub. With *Check for releases daily* off, the panel asks only when you press *Check now*.

### What's new

**Import outbounds and endpoints**
- The Outbounds and Endpoints pages have an import menu: paste share links (one per line, or a base64 block) to get outbounds; drop a WireGuard `.conf` or an `.ovpn` file to get an endpoint; or sign in to **NordVPN** (access token or NordLynx key) or **PIA** (username and password) and pick servers from the provider's live list to get WireGuard endpoints.
- You see every row before anything is saved, and can edit its tag. Each row is then created the ordinary way, so every check a save applies still applies. A provider's token or password is used for that one request and not stored.

**ShadowTLS, Shadowsocks and MTProxy**
- **ShadowTLS now serves through a detour.** Inbounds have a *Listen options* section whose detour names the inbound a ShadowTLS inbound hands its connections to; a ShadowTLS inbound needs one, and its version is a 1/2/3 choice. sing-box and Clash subscriptions carry the pair; links and Xray do not.
- **Shadowsocks 2022 keys fit their method.** The key generator made AES-128 keys only; it now follows the method, changing the method re-keys an inbound whose key no longer fits, and a key of the wrong length is refused on save.
- **MTProxy has a FakeTLS site of its own** per inbound (empty keeps `www.cloudflare.com`, so no secret changes), and **users get a Telegram link**: on the subscription page with an *Open in Telegram* button, in the QR dialog and in the export.

**Users and subscriptions**
- **Add or remove a template on many users at once**, from the selection menu or on the current filter. Every other template each account is on stays as it is.
- **Choose an inbound's place in subscriptions** with an order number on its Basic tab (#12). Lower comes first; at the default 0 nothing moves.
- **Usage by month, and as CSV.** The node's per-user usage and a user's usage by node pick a window (the presets or one of the last twelve months, in the Persian calendar in the Persian UI) and download it as a sheet. Per-user traffic older than 30 days is folded into days, which keeps the database small without losing a byte of the totals.
- **Config files keep their extension.** Safari and Chrome on Android saved a WireGuard `.conf` or an `.ovpn` as `.conf.txt` / `.ovpn.txt`, and no app opened it; the subscription page and the QR dialog now save them as they are named. A theme of your own does the same with `dataURI "application/octet-stream"`.

**WARP**
- **WARP+ licence key** on a WARP outbound moves its account onto a key you bought or earned. Each node is a WARP device of its own and a key covers only a few devices; past that, Cloudflare refuses the key and the node stays on free WARP, saying so in its log. **Needs node v0.1.2.**
- A template whose WARP outbound names one profile (id and token) on two or more nodes now carries a warning: the nodes share one WARP device. The save is not refused.
- The generate button is gone from the WARP key fields; a made-up value is never right there.

**OpenVPN**
- sing-box subscriptions pin the OpenVPN server's certificate name, as the `.ovpn` does.
- A certificate with no name on it (Let's Encrypt's short-lived certificates for an IP address) is pinned by its fingerprint. A renewal changes the fingerprint, so users download their file again after one; the file and the node's warning say so.

### Safer by default

- **The panel refuses writes another page sends.** A page on another origin of the same site (an addon on a subdomain, another port) could post to the panel with the operator's login; such requests are now refused.
- **Cookies:** over HTTPS the login cookie is `Secure` with the `__Secure-` name, it is bound to the path of the panel's route, and it is `SameSite=Strict`. Changing a route's prefix signs everyone out there.
- **Nothing in a config can start a program on a node.** OpenConnect's wrapper paths, Tor's executable path, extra arguments and transport plugins, and Tailscale's SSH server are refused on save, with the option named. A row saved before keeps working: the option is left out of what the node is sent.
- **Templates are checked before they reach a node:** a template that selects one tag twice is refused, and so is an update that drops a row a route or selector still names. Through the API an update writes only the fields it carries, a name used by another template answers 409, and a missing outbound or template 404.
- **Panel releases are signed**, and the update button checks the signature before it takes a backup or downloads anything.

### Smaller things

- A weekly reset cycle anchored on Sunday is kept on Sunday. Accounts and plans created with a Sunday anchor before were stored with Monday and cannot be told apart from a real Monday; check them.
- Node health history is folded again on panels with a long history; before, its table could keep growing.
- An outbound check through a server that never answers now says *timed out* instead of *the node did not answer*.
- Fixes from a review of every change since v0.1.1.
- Updated dependencies; built with Go 1.27.4, which fixes a security issue in its HTTP library.
