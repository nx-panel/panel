## NX Panel v0.1.1

### Before you update

- **This release installs from the update button** (Settings → Panel update), or with the install script as before.
- **Take a backup first.** A backup restores only into the version that took it.
- **Update the panel first, then the nodes.** This panel works with nodes on v0.1.0. Node v0.1.1 brings the new certificate features on a node (below) and fixes OpenConnect clients dropping right after they connect (node #1).
- **OpenVPN users download their `.ovpn` file again** (or their subscription). The old files keep failing in OpenVPN Connect; see *OpenVPN* below.
- **Docker installs:** the theme catalogue writes into `./sub-themes`, which the new compose file mounts writable. If yours mounts it read-only (`:ro`), drop the `:ro`; an install into a read-only folder says so.

### What's new

**Choose the addresses each tunnel dials**
- A tunnel used to dial every link address of the node it connects to, or its management address when it had none. Each origin now has an address section: leave it on *All addresses*, or pick the addresses yourself, in failover order, including the management address and addresses the node does not list.
- **Node addresses for tunnels** on the Tunnels page sets, per node, the addresses every tunnel dials when its section is *All addresses*.
- Editing a node's address or link addresses now resyncs the tunnels on both ends at once, instead of leaving them on the old address.
- The tunnel form has two tabs: the nodes and their addresses, then the profiles.

**Tunnel status as a diagram**
- The status dialog draws the tunnel: users, the relay with the addresses it is dialed at, each origin and the internet, one line per origin and address, coloured by what the dialing side reports. Choosing a line shows its profiles, links, backoff and the last error. A failing address gets a hint once the reports point at the path or at the node's addresses. The tables of before are under *Every detail as a table*.
- A tunnel's usage graph lists only its relay and current origins, and reads each half the way the node counts it.

**Certificates**
- **dns-01 gains ArvanCloud, Selectel, Tencent Cloud (DNSPod) and Huawei Cloud**, beside Cloudflare, Alibaba Cloud and acme-dns. The form shows the credential shape of each.
- **Names are checked before the authority is asked.** A name with no address, one behind Cloudflare or ArvanCloud, or one pointing elsewhere than the server that issues comes back as a warning, and the page asks *issue anyway?*. A wildcard over http-01 or tls-alpn-01 is refused at once, since an authority issues one only through dns-01.
- A node's ingress inbound answers the tls-alpn-01 challenge on the port it holds, so a node certificate is issued and renewed without stopping the inbound. **This and the four new providers need node v0.1.1** on the node that issues.
- **Verify peer cert by name** in a certificate's or an inbound's client settings (#10): names, comma-separated, that Xray apps check the server's certificate against instead of the SNI. A link can then send another SNI and still verify an ACME certificate, with no pin to change at every renewal. It goes into links as `vcn` and into Xray subscriptions as `verifyPeerCertByName`; sing-box and Clash apps have no such option. The panel does not check the names against the certificate: if they are not on it, Xray apps refuse the connection.

**Hysteria2: gecko obfuscation**
- A Hysteria2 inbound or outbound with an **Obfs password** now has **Obfs type**: *salamander*, as before, or *gecko*, which also splits each connection's opening handshake into randomly sized, padded pieces. **Gecko min/max packet size** set the range (empty is 512–1200, at most 1452).
- Only newer apps speak gecko: Hysteria 2.9.2+, sing-box 1.14+, mihomo 1.19.26+, Xray 26.9.30+, v2rayN. v2rayNG imports a gecko link as salamander and does not connect. Add a gecko inbound beside a salamander one rather than switching the one in use.
- Xray subscriptions now carry obfuscated Hysteria2 entries (salamander and gecko); before, they were left out.
- Nodes on v0.1.0 already serve gecko; nothing to update on the node for it.

**Subscription page themes from the catalogue**
- **Settings → Subscriptions → Catalogue** browses the themes of the public catalogue and installs, updates and removes them with one click. The catalogue is cached on the server, so opening it never reaches the internet; *Refresh* downloads it again. A theme folder the panel did not install is never touched.
- **Theme catalogue address** (main admin) points it at a mirror, for networks where GitHub is slow or blocked.

**Resellers: spent traffic stays spent**
- A reseller's allowance is now charged to a ledger as the traffic is used, at the node's multiplier of that moment. Deleting an account, or handing it to another owner, no longer gives a reseller its traffic back. The upgrade fills the ledger from the old figures, so no reseller's spend moves.

**OpenVPN**
- `.ovpn` files now verify in OpenVPN Connect, with a Let's Encrypt certificate and with the panel's self-signed one: the file carries the whole chain up to its root, checks the server by its extended key usage, and pins the certificate's name. Users download their file again.

**WireGuard address ranges**
- A user's WireGuard address follows the account id, so a range fills by the highest id, not by the number of accounts. The node's warnings now say how many accounts an endpoint left out and the highest id its range has room for. New WireGuard, OpenVPN and OpenConnect endpoints start at a /16.

**The free tier** serves 50 users and 2 nodes (it was 25 and 1).

**Smaller things**
- A Hysteria2 or Hysteria link to a self-signed certificate now carries `insecure=1` beside the pin, so the official Hysteria app connects to it (the pin is still checked). Users of that app refresh their subscription.
- An error the panel did not explain now says whether no answer came at all or the answer was not the panel's own (a proxy's or CDN's page), instead of a bare *Error*.
- Fixes found in a review of every change since v0.1.0, across certificates, the theme catalogue, tunnels and the licence.
- Updated dependencies, including a fresh root certificate set for the panel's outbound connections.
